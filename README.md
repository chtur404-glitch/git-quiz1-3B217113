# Git 實作小考：接手一個現有專案

這次小考不是背 Git 指令。

你會接手一個已經有版本歷史的小專案，再依照幾個實際情境整理它。請先判斷問題，再決定要用哪些 Git 指令。

## 作答方式

1. Clone 這個 Repository 到自己的電腦。
2. **不要刪除 `.git`，也不要重新 `git init`。** 題目原本的 commit 歷史也是評分內容。
3. 在 `SUBMISSION.md` 填寫學號與姓名。
4. 依序完成下面四個工作。
5. 建立自己的 **Public GitHub Repository**，名稱請使用 `git-quiz1-學號`。
6. 將完成後的專案與完整 commit 歷史推送到自己的 Repository。
7. 最後只需繳交自己的 GitHub Repository 網址。

> 不限制你使用 CMD、VS Code 或 GitHub Desktop。評分重點是最後的專案狀態與 commit 歷史是否合理。

---

## 工作一：整理不該放進版控的個人設定（20 分）

你發現 `.vscode/settings.json` 已經被放進 Git 版控。

這是個人的 VS Code 工作區設定。現在希望：

- 本機繼續保留 `.vscode/settings.json`。
- Git 從現在開始不要再追蹤 `.vscode`。
- 未來 `.vscode` 裡面的檔案也不要再被加入版控。
- 完成後要留下合理的 commit 記錄。

請自行處理。

---

## 工作二：同一個檔案，同時有三個版本（25 分）

專案中的 `version.txt` 目前是：

```text
v1
```

請依照下面情境操作：

1. 把 `version.txt` 改成 `v2`，並讓 Git 準備在下一次 commit 提交這個版本。
2. **先不要 commit。** 再把工作區中的 `version.txt` 改成 `v3`。
3. 此時先用 Git 指令確認差異，想清楚「已提交、準備提交、目前工作區」分別是哪一版。
4. 接下來建立兩筆 commit，讓 Git 歷史中的 `version.txt` 依序留下：

```text
v1 → v2 → v3
```

限制：

- 第 2 步完成後，不可以為了作答方便把檔案重新改回 `v2`。
- Commit Message 請自己決定，但要讓人看得懂這次修改的目的。

老師會直接查看 commit 中的檔案內容，不只看最後的 `v3`。

---

## 工作三：修正程式，但不要把不相關的工作混在一起（30 分）

執行：

```bash
python app.py
```

目前會看到：

```text
成績統計
人數: 5
平均: 72.0
及格人數: 4
```

但這 5 筆成績的正確平均是 **72.6**。

請完成兩件事：

### A. 修正平均成績

找出程式中的問題，讓執行結果變成：

```text
平均: 72.6
```

### B. 補充使用說明

在 `USAGE.md` 補上一小段說明，讓第一次拿到專案的人知道輸出中的：

- `平均` 是所有成績的算術平均。
- `及格人數` 是成績大於或等於 60 分的人數。

這兩件事彼此沒有直接關係。

請安排合理的 commit，讓未來查看 Git 歷史的人可以清楚分辨「程式修正」與「文件修改」。Commit Message 也要能說明每次修改做了什麼。

---

## 工作四：完成交付（25 分）

完成前三項工作後，整理 Repository：

- 在 `SUBMISSION.md` 填好學號與姓名。
- 確認主要分支是 `main`。
- 確認不該追蹤的檔案沒有出現在 GitHub 最新版本。
- 確認 `python app.py` 可以正常執行，而且平均為 `72.6`。
- 查看自己的 commit 歷史。不要留下 `update`、`test`、`123` 這類無法理解目的的訊息。
- 將完整結果推送到自己的 GitHub Public Repository。

### 繳交前，你的 GitHub 應該能讓老師看出

1. 你保留了題目原有的版本歷史。
2. `.vscode` 原本被追蹤，後來已經正確停止追蹤。
3. `version.txt` 的 commit 歷史確實是 `v1 → v2 → v3`。
4. 平均成績已修正為 `72.6`。
5. 程式修正與文件修改沒有混在同一筆不清楚的 commit。
6. Commit Message 可以看懂每次修改的目的。

---

## 評分方式

| 項目 | 配分 |
|---|---:|
| 正確處理已被追蹤的 `.vscode` | 20 |
| 正確理解暫存區，留下 `v1 → v2 → v3` 歷史 | 25 |
| 修正程式並合理拆分 commit | 30 |
| Repository、commit 歷史與最後交付品質 | 25 |
| **總分** | **100** |

## 注意

這份小考會看 **Git 歷史**。

如果把題目下載成 ZIP、刪除 `.git` 後重新建立 Repository，雖然最後檔案可能看起來一樣，但原本的版本歷史會消失，會影響成績。
